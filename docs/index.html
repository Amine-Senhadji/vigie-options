Ce qui bougesous la surface

Trois agents Claude Code passent chaque jour au crible les options de ta watchlist. Python fait les calculs, les agents les décrivent, et aucun ne te dit quoi acheter.

Trois agents,
un seul travail chacun

Ils s'enchaînent chaque matin avec la commande /bourse. Chacun n'a accès qu'aux outils de son rôle : la vigie, par exemple, ne peut exécuter aucune commande.

1

Collecteur

Récupère les cours, la chaîne d'options des échéances à moins de 60 jours, l'open interest et les dates de résultats.

Ne fait jamais : estimer une donnée manquante. Elle reste « indisponible ».

2

Analyste

Décrit l'activité de chaque titre par rapport à son propre historique, à partir de chiffres calculés et testés en Python.

Ne fait jamais : qualifier une activité de haussière ou de baissière.

3

Vigie

Sort au plus cinq titres à regarder, chacun avec son explication la plus banale et un niveau de confiance.

Ne fait jamais : recommander un achat, une vente ou une taille de position.

Fait pour être vérifié,
pas cru sur parole

  • Calculs en Python, 29 tests sans appel réseau, CI sur Python 3.10 à 3.12.
  • Une donnée manquante reste « indisponible », jamais estimée.
  • Un open interest nul, figé ou en retard d'une séance est repéré.
  • Les positions ouvertes se mesurent sur les contrats les plus échangés.
  • Pas de collecte en pleine séance : les volumes seraient partiels.
  • Nouvelles échéances et échéances mensuelles sont signalées.
  • Un journal compare chaque signalement à J+14 aux titres non signalés.

Installer en quelques commandes

git clone https://github.com/Amine-Senhadji/vigie-options.git
cd vigie-options
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
claude          # puis tape /bourse
Voir le code sur GitHub

Python 3.10 ou plus récent et Claude Code requis. Outil de recherche personnel : rien ici n'est un conseil en investissement. Le volume d'options ne donne pas la direction, car chaque contrat a un acheteur et un vendeur.
